## 1. 背景

- 千葉県佐倉市の洋菓子店。浸水の被害から復旧中で、**10月17日に営業を再開する予定**
- Instagramは、働いている人全員が関わる。ふだんはアルバイトが、接客の合間にストーリーズを上げる。アルバイトがいないときは、シェフが上げる
- 端末は、自分のスマホの人と、シェフの端末を使う人がいる
- 学生のプロジェクトとして作っている。効果は「作業時間が減ったか」で確かめる。**発表は10月23日**
- プロジェクトが終わったあとも、お店だけで使い続けられることが条件

### 今、困っていること

1. 営業中のストーリーズに「10.06」「OPEN」の文字やスタンプを毎回手で入れ、全体が可愛く見えるかを毎回判断している
2. 雨の日の「足元にお気をつけてお越しください」のような、ていねいな一言をその場で考えるのが面倒
3. 新作や季節の商品で、味について書くべきか迷い、画像だけになる
4. 考えている間にお客さんが来て中断され、戻るとやり直しになる
5. 営業カレンダーを、シェフが毎月一から作り直している
6. 誰が作るかで、見た目がばらつく

### 解決の考え方

**言葉とデザインを、その場で考えない。あらかじめ用意しておき、えらぶだけにする。**

## 3. 機能

### 3-1. 最初の画面(スタッフの画面)

- 「営業中」「新作・季節」「駐車場」「営業カレンダー」の4つからえらぶ
- 確認の時期には、いちばん上にお知らせを出す(3-5)。「確認する」を押すと、管理ページのカレンダー確認画面を直接開く
- 自動投稿が失敗したとき、または自動実行が2日以上動いていないときは、いちばん上に表示する(3-11)
- 前回の作りかけがあれば、その続きから始まる
- メニューに「登録・確認(お店の人用)」を置き、管理ページを開く

### 3-2. 営業中(毎日、かならず使う。いちばん大事)

1. ショーケースの写真をえらぶ(その場で撮ることもできる)
2. 日付(今日。`10.07` の形)と「OPEN」が、決まったデザインで自動で入る
3. ひとことを、状況(雨の日、暑い日など)→ 言葉の順にタップしてえらぶ。えらばなくてもよい
4. 日付とOPENを上に置くか下に置くかを切りかえられる
5. 営業時間が設定されていれば、小さく入れる
6. 保存する、または共有する

動画を上げるときは文字を入れられないので、えらんだひとことをコピーするボタンを用意します。

### 3-3. 新作・季節

1. 登録ずみの商品をえらぶ
2. 写真をえらぶ
3. 商品名と、ひとこと説明が入る。ラベルは「NEW」「季節限定」「本日のおすすめ」「なし」からえらぶ
4. 色は、商品ごとに決めた色(ピンク、茶色、緑、黄色、むらさき)を使う

### 3-4. 駐車場

- 設定しておいた案内文が、1タップで画像になる
- 写真を入れるかどうかをえらべる

### 3-5. 営業カレンダー

**スタッフの画面**:確認ずみのカレンダーを見ることと、画像にして保存することだけができる。

**管理ページ**:

- 年と月をえらぶと、定休日があらかじめ入った状態で出る
- 日にちをタップするたびに、「お休み」→「時間変更」→「営業」と切りかわる
- 「定休日どおりに戻す」ボタン
- ひとこと(例:「23日は営業します」)を入れられる
- 大きさは、ストーリーズ、フィード投稿、店頭掲示用のA4
- 休みの日数を表示し、「この内容でOK」を押すと確認ずみになる
- OKを押すと、そのときに描いた画像(JPEG)について、次の3つを行う。
  1. 原本を、Googleドライブの非公開のフォルダに置く
  2. 公開用の写しを、GitHubの `calendar/YYYY-MM.jpg` に置く
  3. シートに予約の行を作る
- 確認のあとに日にちを変えたら、確認を取り消す。予約も取り消しにする

**日程**(日にちは設定で変えられるようにする):

| 日 | 起きること |
|---|---|
| 20日 | アプリにお知らせが出て、LINEでも知らせる |
| 23日 | まだ確認していなければ、もう一度LINEで知らせる |
| 25日の12時台 | 確認ずみなら投稿する |
| 25日より後 | 25日までにOKがなければ投稿しない。あとからOKが出たら、次の実行(1時間以内)で投稿する |

- アプリを使い始める前の月については、お知らせを出さない
- 管理ページに「お知らせの表示を試す」ボタンを用意する(実演と動作確認のため)
- **フィードとストーリーズのどちらに投稿するかは、まだ決めていません。設定で選べるようにして、初めの値は計画のときに私に聞いてください**

### 3-6. 登録(管理ページ)

**ひとこと集**:状況ごとの一覧。足す、直す、しまう。状況は、すでにあるものからえらぶか、新しく書く。

**商品メモ**:商品名、ひとこと説明、色。足す、直す、しまう(次の季節にまた使うため、消さずに隠す)。

**お店の設定**:営業時間、営業中の色、駐車場の案内(1行に1つ)、定休日(曜日)、カレンダーの日程(20日・23日・25日・12時)、投稿先(フィード/ストーリーズ)。

**登録できる人**:アプリの中には一覧を作らない。管理ページに「登録できる人を足すには、シートの共有から足してください」と案内と手順を出す。

**共通の決まり**:

- 価格のように見える文字(「500円」「¥500」など)が入っていたら、登録させず、理由を表示する(お店の方針で、価格は載せません)
- 「例を入れる」ボタン。入れた例には「例」の印をつける
- 消す(しまう)ときは、一手間を入れる

### 3-7. AIに頼む文をコピーする(管理ページ)

アプリからAIを呼び出しません。無料のAI(GeminiやChatGPTなど)に貼り付ける文を作って、コピーできるようにします。

- **ひとこと**:「こういう状況」を入力すると、「ていねいな日本語、30字以内、価格や不確かな事実は書かない、絵文字なし、5つ」という条件つきの依頼文ができる
- **商品の説明**:商品名と短いメモを入力すると、「40字以内の1文、メモにないことは足さない」という条件つきの依頼文ができる

出てきた案は、シェフが読んでから登録します。お客さんに出るのは、登録された言葉だけです。

### 3-8. 保存と共有(スタッフの画面)

- 画像はJPEGで出す
- スマホでは、端末の共有機能(Web Share API、ファイルつき)でInstagramに渡せるようにする。使えない端末では、保存ボタンだけを出す
- 営業中と新作・季節は、写真がないと保存できない(理由を表示する)
- **写真は端末の外に送らない**

### 3-9. 中断しても続きからできる

- えらんだ種類、日付、ひとこと、商品、ラベル、文字の位置を、端末に保存する
- えらんだ写真も、長辺1920ピクセルに縮めて端末に保存する
- 保存した内容は、その日のうちだけ使う。日付が変わったら、まっさらな状態で始める
- 「新しい投稿を作る」ボタンで、いつでも消せる

### 3-10. 作業時間の記録

- 内容に触りはじめてから保存(または共有)までの秒数を、公開窓口に送り、シートに追記する
- 入れるのは、日時、種類、大きさ、秒数だけ。名前や端末の情報は入れない
- 一覧と平均は、管理ページで見られる。表計算ソフトに貼り付けられる形(タブ区切り)でコピーできる
- 送れなかった記録は端末にためておき、次に開いたときに送る

### 3-11. 自動投稿(GASの毎日の自動実行)

検討書の「自動投稿の失敗への備え」の節にある状態図のとおりに作ってください。

- 予約の状態:確認済み → 投稿中 → 投稿済み。ほかに、失敗、要確認、取り消し
- 実行は1時間ごと。「投稿日の12時を過ぎていて、確認済みで、まだ投稿済みでない」予約を探す
- ロックをかけてから「投稿中」にする。同じ予約を2つの処理が同時に扱わない
- 投稿の前に、公開用の画像のURLが開けて、大きさが予約の記録と一致することを確かめる
- Instagramの下書き(コンテナ)を作ったら、そのIDをすぐシートに書く。準備完了の確認は1分おきに行う。GASの6分の制限に近づいたら、次の実行に引き継ぐ(下書きは24時間有効)
- 公開に成功したら、投稿のIDを書いて「投稿済み」にする
- はっきりしたエラーは「失敗」にし、1時間後にやり直す(最大3回)
- **公開の結果が分からないとき(通信の途切れなど)は「要確認」にして、自動ではやり直さない**。管理ページに最近の投稿を並べ、シェフが「投稿済みにする」か「もう一度出す」を選ぶ
- トークンが無効になったときは、やり直さずにすぐ知らせる
- 失敗が3回続いたとき、要確認のとき、トークンが無効のときは、LINEで知らせ、アプリにも表示する
- 最後に正しく動いた日時を配信データに入れる。2日以上古ければ、アプリに表示する(自動実行が止まったことに気づくため)
- どの状態からでも、管理ページからカレンダー画像を保存して、手で予約投稿できるようにする(逃げ道)

### 3-12. LINEの知らせ

- 送るのは、確認のお知らせ(20日、23日)、失敗の知らせ、GitHubのトークンの期限が近い知らせ(切れる30日前)
- 文には、アプリへのリンクをつける。LINEの中のブラウザではなく、いつものブラウザで開く指定をつける
- 友だち全員あての送信を使う。**お客さん向けのLINE公式アカウントでは絶対に送らない**(お客さんに届いてしまうため)。説明書にも強く書く

## 4. データとログインの守り方

### だれが何をできるか

| 入り口 | だれが | できること |
|---|---|---|
| スタッフの画面 → 公開窓口 | だれでも(URLを知っていれば) | 配信データを読む。作業時間の記録を1件ずつ足す |
| 管理ページ | シートの編集権限を持つ人 | 登録、直す、しまう、カレンダーの確認、記録を見る |
| 毎日の自動実行 | GASの持ち主の権限で動く | 予約を読み、投稿し、結果を書く |

### 決まり

- **書きこむ入り口は2つだけ**:管理ページと、公開窓口の「記録の追記」。公開窓口は、記録の追記のほかは読むことしかできない
- **配信するのは、お客さんに見せてよいものだけ**:ひとこと、商品、投稿に使う設定、確認ずみのカレンダー、自動投稿の状態。作業時間の記録、確認前のカレンダー、予約の詳しい中身は配らない
- **同時に保存しても壊れない**:保存はGASのロックで1件ずつ処理する
- **後からの保存が前の変更を消さない**:管理ページは、開いたときの版番号をつけて保存する。違っていたら保存をことわり、「ほかの人が先に変えました」と表示して読み直す
- 保存するたびに、設定のシートの版番号を1つ上げる。シートを直接直したときも上がるように、編集を検知するトリガーを入れる
- 行には変わらないIDを振る。並べる順番は別の列にする
- 消さずに「しまう」
- 日付は「2026-11-01」のような文字で持つ。時刻は日本時間にそろえる。シートの日付型は使わない
- 見出し行とIDの列は保護し、選ぶ列には入力規則をつける
- 配信の前にすべての行を検査し(必須の項目、文字数、選べる値)、合わない行は配信から外して、管理ページに「直してほしい行」として出す
- 記録の追記は、決まった項目だけ、型と範囲が正しいものだけを受けつける。いたずらで大量に書かれたときの対策も、計画で説明してください
- **画像の場所は「calendar/2026-11.jpg」のような場所だけをシートに書く**。URLの頭の部分は、設定の1か所に置く(GitHubのURLが変わっても、1行直すだけで済むように)

### 秘密の情報

| 情報 | 置き場所 | 権限・期限 |
|---|---|---|
| Facebookページのアクセストークン | スクリプトプロパティ | 投稿に必要な権限だけ。期限なし |
| GitHubのトークン(細かい権限のもの) | スクリプトプロパティ | このリポジトリだけ、Contentsの読み書きだけ。期限1年。期限の日もプロパティに書き、30日前にLINEで知らせる |
| LINEの長期のチャネルアクセストークン | スクリプトプロパティ | 期限なし |

- 秘密の情報は、私がGASのエディタの画面から手で入れます。**あなた(Claude Code)は、秘密の情報を受け取ったり、ファイルに書いたり、表示したりしないでください**。入れる場所と名前だけを決めて、説明書に書いてください
- MetaのアプリシークレットはGASにもリポジトリにも置かない
- リポジトリは公開です。だれに見られてもよいものだけを置く。`.gitignore` と、GitHubの秘密の検出の設定を確認してください
- GAS、シート、ドライブのフォルダのIDや、公開窓口のURLも、コードに直接書かず、画面側は設定ファイル1つ、GAS側はスクリプトプロパティにまとめる

## 5. できあがる画像のデザイン

お店が今出している投稿の雰囲気に合わせます。

- 写真を画像いっぱいに敷く。枠や色の帯で囲まない
- 文字は白い手書き風。タイトルには、色つきの影(右下に少しずらした縁取り)をつける
- 見出しやラベルは、筆でさっと引いたような色の帯の上に、白い文字をのせる
- 小さな文字には、濃い色の細い縁取りをつけて、写真の上でも読めるようにする
- 飾りは、小さなきらきらとハートを少しだけ
- 写真の上下に、うすい影のグラデーションを敷く
- 書体はGoogle Fontsの「Potta One」(タイトル、OPEN、商品名)と「Yusei Magic」(ひとこと、説明、カレンダーの数字)。読み込めないときは、端末の丸ゴシックで代用する
- 駐車場と営業カレンダーは、うすいクリーム色の地に筆の帯の飾りを置く

**画像を描くコードは1つだけにする**。スタッフの画面と管理ページの両方が、GitHub Pagesに置いた同じファイルを読みこみます。管理ページで確認した画像と、アプリで作る画像の見た目がずれないようにするためです。

| 種類 | ピクセル | 文字を置かない範囲 |
|---|---|---|
| ストーリーズ | 1080 × 1920 | 上250、下270 |
| フィード投稿 | 1080 × 1350 | 上下90 |
| 店頭掲示 A4 | 2480 × 3508 | 上下130相当 |

**文字の折り返し**:1行に収まるなら少し小さくしてでも1行にする。2行になるときは、最後の1文字だけが次の行に落ちるのを避け、長さをそろえる。助詞や読点のあとで切るのを優先する。商品名は幅に合わせて小さくし、それでも入らなければ2行にする。

## 6. 画面と言葉づかい

- 画面の言葉は、やさしい日本語にする。カタカナの専門用語や英語は、できるだけ使わない
- ボタンは、押すと何が起きるかをそのまま書く
- うまくいかなかったときは、何が起きたかと、どうすればいいかを書く
- 指で押しやすい大きさにする。画面が横にはみ出さない
- 明るい表示と暗い表示の両方に対応する
- ホーム画面に追加して、アプリのように開けるようにする
- **管理ページは、スタッフの画面と同じ色・文字・ボタンの形にする**(同じCSSファイルを読みこむ)。上に「アプリに戻る」を置く

## 7. 配り方と、動かし続けるための決まり

- **電波がないとき**:一度開いたことがあれば、端末に保存した配信データで画像を作れる。配信データは、開いたときに裏で新しい版を確かめる
- **新しい版がすぐ届くこと**:直して公開したら、次に開いたときに全員が新しい版になる。古い版が端末に残り続けないようにする
- **LINEなどの中の画面で開かれたとき**:「SafariかChromeで開いてください」と案内する
- **配り方**:URLのQRコードを作る方法を説明書に書く
- **管理ページの埋めこみ**:管理ページをスタッフの画面の中に埋めこんで使えるか(iPhoneのSafari、ホーム画面から開いたとき)を試し、結果を報告してください。ログインが通らなければ、「開いて戻る」形にします

## 8. 作らないもの

- 残りわずか、完売、焼き上がりの投稿
- アプリの中でAIが文章や画像を作る機能
- 営業カレンダー以外の自動投稿
- LINEからの受け取り(Webhook)。GASの受け口ではLINEの署名を確かめられないため
- InstagramのDMでの知らせ
- 動画への文字入れ
- アルバイト一人ひとりのアカウント
- アクセスの解析や、外部への記録の送信(3-10をのぞく)

## 9. 分かっている限界(説明書にも書いてください)

- 自動投稿は12時ちょうどではなく、12時台に出る
- 管理ページの上には、Googleの注意書きが出る。初めて開くときだけ、許可の画面が出る
- 配信データは、URLを知っていれば誰でも読める。お客さんに見せてよい内容だけを登録する
- 作りかけの内容と写真は、端末ごとに保存される
- シェフの名義に移すとき、スタッフの画面のURLが1回変わる
